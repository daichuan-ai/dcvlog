# DCVlog V1.0.5 → V1.5.1 实机开发记录

## V1.0.5 基础能力
形成采访式创作法：一次一个问题、卡壳救援、多客人装配、前5秒、结尾、本人语气定型；AI保护真人语料，不直接替化妆师编专业判断。

## 安装与身份修复阶段
统一身份为 `daichuan-ai / dcvlog / /dcvlog`，学员安装优先直接复制 Skills CLI 命令，避免宿主把“安装”误解成“创建”。

## V1.1.x 开场/素材/真实性修复
- 前5秒后置；
- 固定四方向：强画面、强情绪、强数字、纯文案钩子；
- 标准镜头默认已拍齐；
- 训练特殊素材雷达；
- 练习对象可正常称“客人”；
- 强数字必须有可展示画面。

## V1.2.0 交互与写作边界
- 所有选择粗体编号；
- 旁白禁止直白自夸；
- 人设结尾有犹豫就放过；
- 最终语气先试读再选择；
- 每个新对话重新填写基础资料。

## V1.3.x 主线采访引擎重构
实机发现采访已经能拿到大量真实素材，但成稿会把素材罗列成采访纪要。

因此改为：
1. 当前客人先选主切口；
2. 主线深挖；
3. 少量辅料；
4. A/B/C素材取舍；
5. 单客人压成短结构；
6. 多客人建立队列并明显递减。

核心原则：
> 采访要尽量拿够事实，成稿不要奖励信息完整，只奖励主线清楚。

## V1.4.0 成熟化妆师旁白模拟
新一轮测试发现：主线清楚以后，最终稿仍可能像“逻辑正确的AI说明文”。此前输入的大量成熟化妆师语料主要被用作专业词库，没有充分参与最终写作。

因此V1.4.0重新定义成熟语料的角色：
- 采访时：帮助学员找到专业表达；
- 写稿时：作为叙事结构、句子节奏、判断插入、动作取舍、结果收束的母语料。

新增后台五种叙事母型，并规定：第一版草稿不能直接交付，必须先经过“成熟化妆师旁白校准”。

目标不是照抄博主，而是让成稿更接近成熟博主已经验证过的讲述机制：人物先行、专业判断藏在现场、动作少而关键、结果出来就停。

运行reference仍保持6个，不继续堆文件。


## V1.4.1 成熟旁白母语料强化

实机复盘发现，成熟语料虽然已经参与“母型判断”，但最终稿仍可能由AI自由组织句子，导致只是专业词更像同行，讲述机制仍像说明文。V1.4.1把成熟语料提升为最终成稿主锚点：每次写稿必须先选1个最相近样本机制，映射句子角色后再生成。

核心原则：**结构向成熟母语料靠，事实向当次采访靠；模仿机制，不移植事实。**


## V1.5.0 服务主线与长度校准

实机复盘发现，V1.4.1虽然已经让成熟语料参与最终成稿，但仍有一个明显偏差：AI容易把所有客人都写成“看脸—分析—调整—变化”，忽略普通客人更常见的真实购买理由——生日、领证、约会、见家长、面试、拍照，以及“不要太浓、想上镜一点、不知道适合什么”等普通需求。

V1.5.0把场景/用途、真实需求、具体问题、变化/反差设为平等主线来源；专业分析只在解释服务决定时出现。与此同时，最终稿新增成熟样本长度硬校准：同类型样本的有效字数、句数和时长成为成稿尺子，避免采访素材越多文案越长。


## V1.5.1 切口、开场、结尾三项实机修复

- 区分当天实际服务人数和本条视频人数，单客不再被多客标签队列劫持。
- 单客主线不清楚时直接给5个明确切口，禁止宽泛人物标签提问。
- 强画面改成化妆师主角型Vlog身份开场；无主角强画面则客人直入。
- 强情绪只用现场原声。
- 结尾命中人设词后直接给3—4秒一句话，最多2个版本；开场/结尾统一使用更强记忆词但不夸大事实。
