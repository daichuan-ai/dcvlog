# DCVlog V1.0.5 → V1.3.1 实机开发记录

## V1.0.5 基础能力

形成采访式创作法：一次一个问题、卡壳救援、多客人装配、前5秒、结尾、本人语气定型；AI保护真人语料，不直接替化妆师编专业判断。

## 安装与身份修复阶段

实机发现：宿主可能把自然语言“安装 Skill”误解为“生成一个新 Skill”；云端/本地环境也可能混淆。最终统一身份为 `daichuan-ai / dcvlog / /dcvlog`，学员安装优先直接复制 Skills CLI 命令。

## V1.1.x 开场/素材/真实性修复

- 前5秒后置，避免小白一开始就被Hook问题卡住；
- 前5秒固定四方向：强画面、强情绪、强数字、纯文案钩子；
- 强画面优先空间、本人审美、动态、特色场景，不默认最终妆后结果；
- 标准镜头默认已拍齐，不再重复问“有没有拍”；
- 逐步训练特殊素材雷达；
- 朋友/模特/互勉/练习对象可正常称“客人”，不必主动暴露练习身份；
- 业务证据若做开场，重点是有没有可展示画面。

## V1.2.0 交互与写作边界

- 任何选择都必须粗体编号、独立分行；
- 客户真实夸赞可保留，化妆师旁白禁止直白自夸；
- 如确实需要评价妆效，用轻松、抽象、比喻、侧面描述；
- 人设结尾只轻问，有犹豫就放过；
- 最终语气先试读，再从自然/松弛/自信/可爱/调皮/幽默/沉稳专业/温柔等选；
- 每个新对话仍重新填写基础人物资料，换取跨平台稳定性。

## V1.3.1 为什么重构

实机成稿暴露出新问题：采访已经能采到很多真实、有价值的素材，但AI会把它们几乎全部罗列进最终文案，导致像“采访纪要/说明文”，而成熟化妆师Vlog通常只抓一个最值得讲的中心。

因此V1.3.1不继续增加补丁，而是重构问答骨架：

1. 当前客人先选“最想讲/记忆最深”的主切口；
2. 只沿主线深挖；
3. 再少量扫描其他真实信息做辅料；
4. 输出前做A/B/C素材取舍；
5. 单客人压成“开场—人物事件—解决—结果画面解释—结尾”；
6. 多客人做明显主次递减。

核心原则：

> 采访要尽量拿够事实，成稿不要奖励信息完整，只奖励主线清楚。

> 一个事实是真的，不代表它值得写进去。
