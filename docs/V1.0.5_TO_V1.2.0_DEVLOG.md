# V1.0.5 → V1.2.0 实机测试与产品决策记录

这份记录用于后续开发，防止已经验证过的问题再次被“修回去”。

## V1.0.5：核心内容逻辑基线

后续版本必须优先保护以下能力：

- 采访式创作：先聊事实，不先写稿；
- AI 先进入目标客户的脑子，再采访化妆师；
- 一次只问一个现实问题；
- 前台像老师坐旁边聊天，后台结构隐藏；
- 用户卡壳时，不继续逼问，先鼓励和给成熟表达参考；
- AI 提示出来的专业表达必须再确认：是否本人真实判断、是否有画面支撑；
- “事实不等于素材”，低价值真话可以不写；
- 多客人先分别采访，再统一装配整条 Vlog；
- 前5秒单独选择真实素材：强画面/真实数字/本人审美人设/文案钩子兜底；
- 正文结束后可做轻人设收口，但不强行升华；
- 完整稿最后再做本人语气定型，只微调口语节奏；
- AI整理优先保护真人语料，不把每句话改成标准 AI 文案腔；
- 提问深度应等于目标观众愿意听懂的深度，不等于老师能讲多深。

## 两轮早期实机采访发现

第一轮证明主采访链能跑，但成稿容易过于结构化、结尾被 AI 强行升华、会出现内部流程泄露。

第二轮出现“脸宽显胖 → 脸侧修容 → 发型做大 → 头包脸”的真实卡壳过程。确认“不知道/说不出来/都不是/你来定”不是普通答案，而是疲劳/卡住信号；这时必须停掉正常追问，改用陪跑救援。

由此形成：聊天式陪跑、成熟语料唤醒、意思确认、画面确认、低价值事实丢弃。

## V1.0.6：独特暗号实验

曾尝试用“代川妆造Vlog编导开工”和固定“川导开工”回执增强路由。

实测结论：如果 Skill 没有被宿主真正发现/加载，暗号再特别也无效。并且固定“川导开工”对普通学员来说生硬难懂，只适合开发阶段验明身份，正式产品应删除。

## WorkBuddy：云端、本地与手机远程不是同一层

实测出现：某个云端任务显示文件已下载并校验，但新的云端任务无法稳定发现；手机远程电脑又可能使用电脑本地 Skill。

因此必须区分：本地电脑 Skill、当前云端沙箱 Skill、宿主持久注册 Skill。

“文件下载成功”不等于“以后所有新任务都能用”。

## V1.0.7：引入 `/dcvlog`

斜杠显式调用比自然语言自动路由稳定。`/dcvlog` 被保留为长期主入口。

但当时仓库仍叫 `dc-makeup-vlog`，内部 Skill 已改成 `dcvlog`，身份不统一。

## 豆包工作：替代 Skill 污染测试环境

一次安装失败后，宿主没有安装 GitHub 真 Skill，而是根据历史上下文自动生成了一个相似 Skill；这个假 Skill 随后出现在技能列表中，内容包含旧六段式、40—50秒、朋友圈框架等，与 DCVlog 无关。

重要结论：

- “聊天里说安装完成”不能作为验收；
- 安装失败时必须禁止宿主创建替代 Skill；
- 必须核对唯一 GitHub 身份；
- 测试前要清理宿主自己生成的假 Skill；
- 安装之前宿主看不到真正 SKILL.md，因此仓库定位问题不能只靠 Skill 正文解决。

## V1.0.8：发行身份统一

最终统一：

- owner：`daichuan-ai`
- repo：`dcvlog`
- Skill name：`dcvlog`
- slash：`/dcvlog`

删除旧仓库后重新建空仓库，只上传干净 V1.0.8，避免旧目录残留。

## V1.0.8 豆包工作真实调用成功

新对话输入 `/dcvlog` 后，宿主成功定位到类似 `/home/user/.agents/skills/dcvlog` 的真实安装目录，读取 Skill 说明并进入采访。

这证明：即使技能选择按钮里暂时看不到，斜杠入口仍可以稳定调用已安装 Skill。

因此验收标准调整：**技能菜单可见是加分项，不再是运行成功的必要条件；`/dcvlog` 能定位真实 Skill 才是当前最关键的实机标准。**

## V1.0.8 调用后发现的两个回归问题

1. 固定“好，川导开工”太像开发口令，普通学员难懂，正式版删除。
2. 新对话直接跳到了“今天这个客人来干嘛”，没有先认识化妆师。原因是此前为了简化调用，把启动逻辑写成“如果上下文似乎知道用户是谁就跳过”。宿主可能利用历史上下文/记忆误判。

V1.1.0 修正为：只看**当前对话线程**是否已经主动提供人物资料。新对话首次使用必须先认识化妆师，除非用户明确要求跳过或继续上次。

## V1.1.0：当前整合基线

完整运行顺序：

`/dcvlog → 当前对话首次人物认识 → 今天客人数 → 逐个客人聊天式采访 → AI后台选唯一主线 → 卡壳救援/证据确认 → 前5秒选择 → 多客人装配 → 可选人设结尾 → 完整连续旁白 → 本人语气定型 → 最终可直接录音版`

后续任何版本如果修改安装、路由或 UI，不得再次删掉上述内容层。


## V1.1.1 → V1.1.3：前5秒不能提前考小白

V1.1.1 把前5秒恢复为硬闸门，但实机继续发现一个体验问题：前5秒属于内容编导能力，比“今天怎么化”更陌生。如果在用户还没建立表达信心前就问“强画面/特别数字”，会增加压力，而且小白经常根本不知道这些词具体指什么。

V1.1.3 统一调整：
- 先完整采访她最熟悉的化妆事实；
- 内容够了以后明确给完成感；
- 再把前5秒作为“采访阶段最后一道题”处理；
- 任何抽象概念都必须翻译成生活化例子；
- 完妆反应可举笑、尖叫、自拍、拉朋友看、真实夸赞；
- 数字可举定金、补尾款、充值、客人数、复购次数/年限；
- 聊天证据可举“档期给我留着”“下次还找你”等；
- 例子只用于唤醒回忆，不能诱导用户编造。

产品判断：前5秒依然重要，但“重要”不等于“要最早问”。正确顺序是先用熟悉任务建立自信，再把陌生的内容能力变成 AI 陪着做的最后一步。


## V1.1.2 → V1.1.3：从“防编”升级为“训练素材意识”

实机继续发现：只在成稿前校验真实性还不够。小白一进入“写文案”状态，会自然地产生“我是不是应该说一个更像内容的答案”的冲动，尤其在第一眼判断、客户诉求、为什么这样改、完妆反馈这些节点。

V1.1.3 的处理不是反复警告“别编”，而是在采访过程中用很轻的一句话把她拉回真实现场：按当时发自内心的第一感觉说；记不清就翻妆前/过程画面；理由说不出先从实际动作倒推；客户没说过的话不补；今天没素材就承认没有，同时顺手建立“下次这种值得留”的采集意识。

目标从“这一条稿子不要虚构”进一步变成：让化妆师形成 `先观察现场 → 顺手留下素材 → 再从素材里找内容` 的长期能力。


## V1.1.3 → V1.1.4：练习对象的叙事身份与业务证据分开

实机讨论确认：新手往往没有真实付费客人，只能先找朋友、模特、互勉或练习对象完成妆造与拍摄。因此不能要求成稿必须主动暴露“这是练习对象”，否则会破坏真实服务式训练。

V1.1.4 统一改为：朋友/模特/互勉/练习对象可以按正常“今天这个客人”来叙述，练习服务可以写得像真实接客；但不得虚构付款、定金、尾款、充值、成交、预约、复购、客户评价、转介绍等不存在的业务证据，也不得补客户没说过的原话。

产品边界一句话：**服务叙事可以像真实接客，硬证据不能编。**


## V1.1.5 → V1.2.0：本轮完整实机反馈收口

本轮测试确认：主体采访因为专业语料和真实化妆逻辑足够，整体已经明显顺畅；主要问题集中在开头、结尾和交互展示，这些属于“执行层”而不是继续增加专业知识。

### 1. 前5秒固定为四个方向，不再让AI自由联想

最终固定：
1. 强画面；
2. 强情绪；
3. 强数字；
4. 纯文案钩子。

每一类只给一个例子，使用粗体编号，让学员直接回复数字。AI不再自行发明第五类，也不把“本人感染力”单独拆出来；本人形象、状态、动作、审美都归“强画面”。

### 2. 强画面不是“最终妆后成品”

三四十秒妆造Vlog如果开头直接把最终妆效完全亮出来，容易提前泄露结果、削弱后续变化期待。

因此“强画面”优先理解为：漂亮/有特色的工作室和装修、颜色和构图抓眼的空间、动态很好的工作镜头、化妆师本人当天特别漂亮/有审美/有感染力、独特少见的场景。

最终妆后默认留到正文后段揭晓。强情绪如果恰好发生在完妆后仍可用，因为它的价值来自情绪，不是单纯“成品好看”。

### 3. 标准镜头默认已拍齐

课程执行已包含固定标准镜头：进门素颜、坐下、沟通、素颜正侧、化妆关键步骤、素颜到妆后变化、手机拍妆后照片并修图、送客、收款等。

因此Skill以后禁止再问“有没有拍到妆后/过程/素颜”等。采访时可以直接让学员翻这些已存在的画面帮助回忆。

只有决定前5秒的特殊素材才需要确认：特色场景/本人审美动态、强情绪、强数字页面等。

### 4. 所有“让学员选”的地方统一视觉格式

只要是开场、卡壳救援、结尾、语气等多选场景，一律粗体编号、独立分行，让学员直接回复数字。不能把多个选项埋在长段落里。

### 5. 旁白不能直白自夸妆面

客户真实原话可以保留“太好看了/很喜欢”。化妆师自己的旁白不能直接总结“这个妆太高级/太绝/太好看”。

如果确实需要本人对结果做一句评价，改用轻松、诙谐、抽象、比喻、修辞或侧面描述，让“好看”被感受到，而不是由化妆师直接宣布。

### 6. 人设结尾是可选项，而且放弃门槛要低

正文和前5秒完成后，可轻问一次是否想留一个带本人特点的小尾巴。成熟样本可参考“我是化妆超好的XX老师，今天就到这里，拜拜”这类有本人记忆点的结尾逻辑。

但只有用户明确愿意、且前面已有清楚、可重复、能被内容证明的特点时才继续。只要出现犹豫、模糊、说不出来，立即放过，使用普通Vlog结尾或无旁白结束。

### 7. 最终语气改成“先试读，再选择”

完成稿后先让学员读两三句，先处理真正拗口的位置。然后提供更多低压力语气选项：自然日常、轻松松弛、坚定自信、可爱、调皮、诙谐幽默、沉稳专业、温柔柔和，以及“全部都给我”。

AI只能轻调句长、连接词、语气词、停顿、口语顺序和少量措辞，不能借语气风格重写事实或硬造段子。

## V1.2.0 当前完整执行顺序

`/dcvlog → 首次人物认识 → 今天客人数 → 逐个客人聊天式采访 → 真实动作/判断与卡壳救援 → 默认标准镜头辅助回忆 → 四方向前5秒选择 → 多客人装配 → 可选人设结尾（犹豫即放弃） → 基础连续旁白 → 自夸检查 → 试读 → 语气编号选择 → 最终可直接录音版`

这套顺序是当前实机基线。后续任何版本新增能力时，优先新增回归用例，不得再次删除已经验证有效的执行层。


## 自然语言安装最终结论

实机验证中，自然语言“安装某某 Skill”可能让宿主在找不到/没识别到仓库时直接创建一个新 Skill，造成测试污染。成熟 DBSkill 博主提供的保底安装方式是直接把 Skills CLI 命令发给 Agent。

DCVlog 当前学员默认安装命令固定为：

`npx -y skills add daichuan-ai/dcvlog -g --all`

安装后重启 App，再用 `/dcvlog` 调用。自然语言安装只作为未来平台识别稳定后的可选体验，不作为当前主教程。
