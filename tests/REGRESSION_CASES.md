# V1.3.1 回归用例

## Case 1｜新对话
`/dcvlog` → 先问年份/年龄段，再城市、从业时间、工作状态/业务。

## Case 2｜今天几个客人 + 队列硬闸门
人物认识后先问“今天一共几个客人”。若回答3个，系统必须先依次拿到3个客人的最小识别标签，不能听到“3个”后立刻只深挖第1个。

## Case 3｜当前客人入口
禁止：`这个客人今天来找你是干嘛的？`

正确：先给5个粗体编号主切口，让学员选最想讲/记得最深的一件事。

## Case 4｜需求不是唯一主线
用户选“前后变化”后，不得又把“生日/拍照/吃饭”重新抢成主线；只有它能帮助理解时才作为辅料。

## Case 5｜辅料扫描上限
主线站住后最多补1—2个其他方向问题，不跑完整问卷。

## Case 6｜卡壳
“不知道/说不出来/你来定” → 暂停普通追问，给2—4个成熟表达参考，粗体编号，允许“都不是”。

## Case 7｜标准镜头
不得询问妆前、过程、妆后、拍照修图等标准镜头是否存在。

## Case 8｜前5秒
最后才问；固定强画面/强情绪/强数字/纯文案；不能新增第五类；强画面不默认完妆结果。

## Case 9｜强数字
没有可展示截图/页面/录屏，不使用数字型开场。

## Case 10｜成稿主线
采访里出现10条真实信息，最终稿可以只保留4—6条。真实不等于必须写。

## Case 11｜单客人结构
最终连续旁白承担：开场 → 人物事件 → 解决 → 结果画面解释 → 结尾。不得写成五个标题或知识点。

## Case 12｜多客人递减
客人1最重，客人2缩短，客人3/4继续缩；最多第1和第2之间一次桥接。

## Case 13｜结果画面解释
不能只是“太好看/太高级”；要把前面判断与画面变化连起来。

## Case 14｜旁白自夸
客户真实夸赞可保留。化妆师自己若要评价作品，只能侧写/比喻/轻松表达。

## Case 15｜人设结尾
任何犹豫立即放过，不硬造差异化。

## Case 16｜语气
先试读；选项1—9粗体编号；只做微调。

## Case 17｜运行文件瘦身
SKILL运行时只能引用6个核心reference；开发日志和tests不得被列为运行必读。


## Case 18｜三客人不能漏写
用户明确“今天3个客人，都要写”。正确流程：先记下3人 → 客人1采访完成 → 客人2 → 客人3 → 所有人完成后才进入前5秒和最终稿。若只写客人1即交稿，判定失败。

## Case 19｜后续客人可以短，但不能跳
第二、第三位采访允许比第一位短，但必须至少拿到各自一个主切口/关键点和一个结果或动作，再决定最终如何压缩。
