# V1.5.0 回归用例

## Case 1｜新对话
`/dcvlog` → 先问年份/年龄段，再城市、从业时间、工作状态/业务。

## Case 2｜多客人硬闸门
回答3个 → 先拿齐3个最小识别标签，再逐个采访；未完成全部客人前禁止写完整稿。

## Case 3｜生日场景不能被带回五官问题
用户：`她今天晚上过生日，还带了黑裙子。`
正确：继续问她想要什么感觉、这个场景影响了什么服务决定。
错误：立刻问`你第一眼觉得她脸哪里需要改？`

## Case 4｜领证可以直接成为主线
用户：`下午三点去领证，想自然一点。`
允许成稿主要围绕领证场景与自然需求，不强制补完整面诊。

## Case 5｜客户普通话不专业也有效
用户：`她就说不要太浓，拍照好看一点。`
不得自动改成“提升面部折叠度/量感”。

## Case 6｜问题型才深挖必要专业判断
用户主线：`每次化妆都显成熟。`
可以追一个真正原因和1—2个关键动作，但仍不做整脸清单。

## Case 7｜变化型
用户：`平时都是甜妹，今天想换个完全不一样的。`
写方向变化，不重新罗列所有五官。

## Case 8｜专业判断不是必答项
场景与需求已经讲通时，最终稿可以没有详细五官分析。

## Case 9｜辅料不能抢主线
主线是生日场景，采访中又出现“眼睛有点肿”。眼睛只在影响服务决定时出现，不能自动升级为整条主题。

## Case 10｜标准镜头
不得询问妆前、过程、妆后、拍照修图等标准镜头是否存在。

## Case 11｜前5秒
最后才问；固定强画面/强情绪/强数字/纯文案；不能新增第五类。

## Case 12｜强数字
没有可展示截图/页面/录屏，不使用数字型开场。

## Case 13｜成熟锚点必须参与
最终稿前必须选择1个最接近的成熟锚点，不能只靠AI默认写作。

## Case 14｜锚点不移植事实
成熟样本是“领证白裙”，当前客人是“生日黑裙”，只能借结构，不能写进白裙/头纱。

## Case 15｜同类型长度比较
场景型最终稿必须优先与场景型成熟样本比较，而不是和问题型长稿比较。

## Case 16｜长度过长
同类成熟样本中位数120有效字，初稿190字 → 必须删到接近108—132字，不得仅改成两个超长复句。

## Case 17｜长度偏短
同类样本120字，但本次真实素材只能完整写80字 → 不允许编客户反馈/专业判断凑到120。

## Case 18｜删除顺序
超长时先删无关背景、第二第三个面部观察、无关步骤、重复解释、结果后升华。

## Case 19｜句子密度
不能为了字数接近，把“背景+需求+五官+动作+结果”塞进一句。

## Case 20｜结果回应主线
前面讲“不想太浓”，结果应回应自然/接受度；不能突然把“脸小了”作为结论。

## Case 21｜结果后停止
客户真实反馈已经完成证明后，不得追加“好的妆容就是……”升华。

## Case 22｜多客人递减
客人1最重，客人2缩短，客人3/4继续缩；总长度与同客人数成熟样本比较。

## Case 23｜人设结尾
用户犹豫就放过，不硬造差异化。

## Case 24｜语气
结构与长度完成后再试读选语气；只做微调，不拉长稿件。

## Case 25｜运行文件瘦身
SKILL运行时只能引用6个核心 reference；开发日志和 tests 不得列为运行必读。
