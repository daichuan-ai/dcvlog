# V1.7.0 实机验收清单

## 1. 启动
- `/dcvlog` 命中 `name=dcvlog`、`version=1.7.0`。
- 每个新对话重新问基础资料，一次一个问题。
- 文案模式首次可出现一次“代川来陪你把今天这条捋出来，咱们直接开始。”；后续不频繁重复。

## 2. 实际服务人数 vs 视频人数
- 先问当天实际服务几位；实际超过1位时，再问本条视频准备讲几位。
- 用户说“实际3位，但视频只讲1位”后，必须立刻按单客视频处理，另外两位退出本条流程。
- 单客视频禁止再问“这个客人大概什么情况/给我一个标签”。
- 多客视频不再先收宽泛标签，按视频顺序逐位采访。
- 只有本条视频要讲的客人全部完成后，才允许进入前5秒、结尾或最终稿。

## 3. 主线来源
- 不再默认问“第一眼看她脸哪里要改”。
- 用户自然说出生日、领证、约会、见家长、面试、拍照等用途时，必须把它作为高价值候选主线。
- 主线来源至少覆盖：场景/用途、真实需求、具体问题、变化/反差。
- 客户普通人的原话可以直接作为素材，不强迫转成专业表达。

## 4. 专业分析边界
- 不要求每篇完整五官分析。
- 专业判断只有在解释真实服务决定时才出现。
- 场景已经足够解释设计时，不得为了显专业硬加中庭、量感、鼻基底等。

## 5. 成熟语料参与最终成稿
- 成稿前必须读取/应用 `makeup-corpus.md` 的服务主线和成熟锚点。
- 选1个主锚点，必要时最多1个辅锚点。
- 模仿结构、信息顺序、句子密度和停止位置，不移植样本事实。

## 6. 长度硬校准
- 最终稿必须与同类型成熟样本比较有效中文字符数、句子数和预计朗读长度。
- 有2—3个可用同类样本时，目标尽量在其中位数90%—110%。
- 只有1个可用样本时，目标85%—115%。
- 明显太长时优先删内容，不用超长复句压缩。
- 主线已经完整但偏短时，不为凑长度编事实。

## 7. 成稿结构
- 结果必须回应开头主线：场景、需求、问题或变化。
- 不得统一写成“变漂亮了”。
- 不得出现采访纪要腔或课堂腔。
- 一个意思成立就走，结果/反馈成立就停。

## 8. 标准镜头与前5秒
- 不问有没有妆前/过程/妆后/拍照/修图/送客/收款。
- 前5秒主体采访结束后才出现。
- 固定四类：强画面/强情绪/强数字/纯文案钩子。
- 强画面必须按“化妆师主角型Vlog开头”处理：工作室/本人强画面 + 身份型短旁白，再进入客人。
- 没有主角型强画面时，允许直接从客人坐下进入。
- 强情绪必须来自真实现场原声，并标“（视频原声）/（现场原声）”。
- 强数字没有真实可展示证据就不用。
- 命中明确开场方向后最多给2个成品，不继续宽泛追问。

## 9. 多客人成稿
- 用户说几个且都要写，就必须覆盖几个。
- 必须执行“第1个讲故事，第2个讲重点，第3个以后看结果”。
- 第2位不能只做机械字数缩短，必须减少叙事层级：只留一个最强新点 + 一个服务决定/处理 + 结果。
- 第3位通常只留一个需求/特点/场景 + 结果；第4位以后可一句带过或画面优先。
- 多客人总时长允许随客人数自然增长，禁止继续硬压在约40秒。
- 单客人20多秒—30/40秒只作为单客参考，不能约束多客整条视频。
- 长度优先与同客人数/相近客人数成熟样本比较；无匹配样本时不设固定总秒数。

## 10. 真人语感
- 保留学员本人鲜活词/客户原话。
- 客户真实夸赞可保留；化妆师旁白不直白自夸作品。
- 语气定型只能在结构和长度锁定后进行。

## 11. 结尾人设
- 结尾默认只有3—4秒，一句话结束。
- 用户只要给出“负责任/审美高/定制化/细节控/有耐心”等明确方向，禁止继续让她解释，直接调用预设库。
- 最多给2个成品结尾让用户选。
- 开场/结尾减少“可能/大概/有一点/比较/稍微”，在事实允许时优先强记忆词；不得编造可核验的第一/唯一事实。

## 12. 运行文件
- 运行时只保留7个核心 references。

## V1.6.1｜拼图入口验收

### Case C1｜只输入 /dcvlog
期望：只显示两个入口“我要开始写文案 / 我要做拼图”，不直接问年龄。

### Case C2｜直接说“我要做拼图”，未上传照片
期望：只让用户选择1张、2—3张、4张、5—6张；选完让用户一次性上传。不得进入Vlog采访。

### Case C3｜“我要做拼图”并同时上传4张
期望：跳过数量选择，直接进入自动排版；默认3:4；1张主图+3张辅助图；不得默认2×2宫格。

### Case C4｜上传1张
期望：可直接做单图作品页；分辨率允许时可从同一原图裁1个细节；不得生成不存在的新脸/新妆面。

### Case C5｜上传6张
期望：有明确主图和次主图，其他为角度/细节；不得机械六宫格。

### Case C6｜用户说“换一版”
期望：保持同一批照片，换版式与标题位置；不重新问流程，不更换人物。

### Case C7｜用户说“第3张做主图，不要中文”
期望：直接修改当前成品，不解释，不重新采访。

### Case C8｜原图保护
期望：拼图只改变画布、裁切、文字、版式；不得改变五官、妆容、肤色、发型、服装。

### Case C9｜问号只用于真正问题
期望：`❓这组照片你想怎么出图？`；`收到4张照片。` 前不得加 `❓`。

### Case C10｜4张选“两种都要”
输入4张并选择3。期望：最终完整交付5张：1张总拼图 + 4张独立作品页。不得只交付其中一类。

### Case C11｜6张选“两种都要”
输入6张并选择3。期望：最终完整交付7张。生成工具若需分批执行，必须继续直到7张齐全。

### Case C12｜工作室名与签名
用户给：`avis美妆`、`川川`，选择拼音。期望：保留`avis`，中文部分转拼音；签名可用`Chuanchuan`；不得擅自创造英文名。

### Case C13｜轻量人味
进入拼图可首次出现“代川很乐意帮你完成，开干。”；进入文案可首次出现“代川来陪你把今天这条捋出来，咱们直接开始。”；后续不得每轮重复。

## 13. 自然语言自维护
- 用户说“更新 DCVlog / 升级 DCVlog / 把 DCVlog 更新到最新版”时，不进入文案或拼图。
- 宿主可执行命令时，直接运行 `npx -y skills update dcvlog -g -y`。
- 宿主不可执行命令时，只返回这一条命令，不得假装更新成功。

## 14. 持续案例库
- `corpus-index.md` 必须存在，并区分 Batch 001 锁定基准与 Batch 002 新增区。
- `batch-001-baseline/cases.md` 必须存在，状态为 LOCKED。
- `batch-002-new/README.md` 必须存在，作为待收录区。
- 用户说“加入 DCVlog 新案例库”时进入案例收录模式，不进入普通 Vlog 采访。
- 新案例原文与 AI 分析必须分开；单个案例不得直接改 `current-patterns.md`。
- 用户说“扫描新案例库，升级当前方法”时，必须比较 Batch 001、Batch 002 与现有 `current-patterns.md`。
- 稳定规律更新后才升级 `CORPUS_VERSION`；案例库升级不强制修改 Skill Version。
- 正式写稿前必须读取 `corpus-index.md` 与 `current-patterns.md`。
