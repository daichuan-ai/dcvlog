# 每次 /dcvlog 自动同步官方最新版

输入 `/DCVlog`（大小写等价的 `/dcvlog`）仍执行原自动更新，不显示“更新／继续使用”选择；随后必须展示约妆/跟妆旁白类型选择并等待。自然语言“更新 DCVlog”作为维护请求调用同一更新器。只说“我要写文案／我要做拼图”不能启动创作，提示先输入 `/DCVlog`，不绕过首屏。

## 实际执行

1. 从宿主本次实际加载的 `dcvlog/SKILL.md` 定位其绝对目录。不要以历史聊天、GitHub版本或另一份全局安装代替真实加载路径。
2. 调用 `python3 "<实际加载目录>/tools/update_skill.py" --skill-dir "<实际加载目录>"`。目录若为符号链接，更新器解析真实落点；开发中的Git工作区会被拒绝自动覆盖。
3. 更新器先通过官方提交订阅/API获取提交，再下载固定提交的完整包；两者不可用时，直接从官方codeload主分支ZIP读取完整提交标识。固定提交tar下载失败时尝试同提交ZIP。ZIP必须带40位提交标识；包内身份、版本与锁定原文通过验证才可安装。只读取标准 `skills/dcvlog/` 内容，不需要系统unzip。相同版本新增案例也能同步。
4. 下载仅在临时目录解包；检查路径、大小、必要文件、版本一致性及19条锁定原文。保留本地新增文件，在实际目录旁保留旧目录备份；替换失败恢复原目录。不扫描、覆盖另一宿主的目录，不触碰 `~/.dcvlog/` 的匿名ID、许可与退出设置。
5. 读取返回JSON。`updated` 或 `up_to_date` 且 `verified:true` 才表示安装文件与本次核对的官方提交一致。不能把“命令退出成功／下载成功／版本号相同”当作校验结果。
6. `updated` 后立即重新读取同一实际目录的新 `SKILL.md` 和当前模式所需参考文件，再进入原有菜单或任务。宿主不支持重读／重载时，提示新开会话；不能声称当前会话已热更新。无需再询问学员是否同意更新。

## 故障与恢复

- 断网、限流、只读挂载或无命令工具：不安装到其他目录，不绕过宿主权限。简短说明本次未能确认／同步最新版，保留可用旧版继续原任务；不显示更新选择题，也不说“已是最新版”。
- `busy`：本次不并发更新，不自动删除锁；另一次更新完成后再试。遗留锁需要先核查。
- `rolled_back`：恢复旧安装，说明未更新；`recovery_required`：保留备份路径并停止使用不完整安装，先恢复。不能通过强制覆盖掩盖错误。
- 备份位于实际目录同级的 `.<目录名>.dcvlog-backups/`，不会自动清理。替换期间宿主若强制终止进程，需核查备份及目录后恢复，不能声称覆盖所有断电情形。
- 更新器不执行下载包中的安装脚本，不读取系统凭据，不上传文案、照片、许可状态或其他用户资料。

## 旧学员的一次性迁移

1.9.2及更早入口没有本更新器；1.9.3旧更新器在部分网络环境也可能无法取得新工具。需按官方 `INSTALL_DOUABO.md` 的“旧版迁移”先完整取得新版并确认实际加载路径，再重新加载。1.9.4更新器允许旧目标只在VERSION标注版本，但仍要求官方发布包的SKILL文件头版本与VERSION一致。不能只凭npx退出码宣布迁移完成；豆包 `.user_skills` 与全局 `.agents/skills` 不共享时必须核对实际realpath。

首次安装命令仍可用于获取官方完整包；Git克隆失败时可改用官方ZIP和Python读取，不应让学员自己排查Git或代理。不同宿主需各自迁移。一旦宿主把执行转入后台，使用其返回的原任务ID读取结果；后台任务不是安装成功。拿不到最终JSON时明确说明未验证成功，不重复启动安装。

只读 `--check` 不替换安装或保存状态；必要时会在临时目录下载并验证包，返回 `latest_version`，再比较实际文件。缺少状态文件不自动等于存在更新。

## 验收边界

本地测试覆盖：跨版本更新、同版本新案例、目标符号链接与双目录、离线／权限不足、完整包检查、备份恢复、保留本地新增文件、后续启动幂等、只读 `--check`。真实豆包、WorkBuddy能否执行命令并重读新文件，仍需分别实机验证。旧 `tools/check_update.py` 只作版本诊断，不能作为新版自动更新已完成的证据。
