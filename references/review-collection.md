# 完稿回收｜仅在学员知情同意、平台支持且后台已开启时执行

这是**独立于匿名事件统计**的可选内容收集功能，不改变采访、写稿质量闸门、作品拼图、查新规则或用户看到的交付内容。

## 三道开关，缺一不可

1. 老师在 `review-config.json` 配置了独立的 HTTPS 收稿地址，且 `enabled: true`；公测包已包含此配置，但后台还必须开启接收。**不要把旧的 `dcvlog-stats` 统计接口当作收稿接口。**
2. 宿主可以实际执行本 Skill 的 `tools/review_upload.py` 并读写本地状态；若不支持或状态检查失败，直接继续主任务，**不得说已经自动回收**。
3. 本次安装环境对当前同意说明版本持有 `agreed` 状态。沉默、跳过、不同意、旧版同意、写入失败均视为无许可，禁止上传。

默认由学员自己决定是否参加；没有明确同意时，默认不收集、不上传。

## 什么时候问、怎样问

每次进入「我要开始写文案」后，静默执行：

```bash
python3 tools/review_upload.py status
```

仅当返回 `{"status":"unset"}` 时，**在正常采访前**只询问这一次：

> 代川想用大家的真实文案，继续改进 DCVlog。你愿意把每次完成的旁白（会隐去明显联系方式，不含聊天记录和照片）自动传给代川用于课程质量分析吗？同意后不用每次再发，随时可以关闭；不同意也能正常写文案。
>
> **1. 同意**  
> **2. 不同意**

- 回复1，执行 `python3 tools/review_upload.py agree`；只有返回 `saved:true` 和 `agreed` 才能记为同意。
- 回复2，执行 `python3 tools/review_upload.py decline`；继续正常采访。保存失败也不得上传，不反复追问。
- `agreed`：不再重复问；`declined`：不再重复问；`disabled`：完全跳过。
- 用户随后说“不再上传/退出收稿”：立即执行 `decline`，尊重拒绝；过往内容的删除需由代川在后台按匿名编号处理，不得宣称已远程删除。

## 什么时间上传、上传哪些内容

只在**用户收到本次完整旁白最终稿后**尝试一次。不上传每轮回答、草稿、讨论内容、客户照片、拼图、个人资料、微信截图或全部聊天记录。

允许上传：

- 最终旁白原文（明显手机号、邮箱、身份证号、微信号由程序再做基础遮盖）；
- `READY` / `LIMITED_DRAFT` 类型标记和本条视频客人数；
- 可选的简短事实依据摘要（最多1600字，只放用户真实确认的场景、审美取舍、实际动作、可见结果，禁止放顾客实名、手机号、工作室地址、原始聊天内容）。

不要为了“收集事实摘要”再采访用户，也不要改动已经生成的最终稿。初级学员回答短，摘要可以为空。不要称基础正则遮盖为完全匿名化；未识别出的姓名或特征仍可能属于个人信息，敏感内容应先排除。

上传路径：

1. 先完成正文写作及事实检查，将本次**已决定要交付**的连续旁白以UTF-8写入仅供上传的临时文本文件（不得用代码命令行参数拼接原文），可选将事实摘要写入第二个临时文本文件。
2. 生成一个新的UUID作为 `submission_id`，一次稿件重试时复用它，防止重复收稿。
3. 调用本地脚本：

```bash
python3 tools/review_upload.py submit --final-file <临时旁白文件> --facts-file <可选摘要文件> --clients <本次视频客人数> --draft-status ready --submission-id <UUID>
```

仅在确实为已获准的缺口试稿时使用 `--draft-status limited`。省略事实摘要时，省略整个 `--facts-file` 参数。命令中的路径须来自宿主实际创建的安全临时文件；**禁止虚构文件、伪造上传结果或把长文案复制进 Shell 命令字符串。**

4. 上传成功或失败都正常交付，不中断写作；不得对学员谎称“已上传”或“所有文案都已收齐”。宿主没有文件或命令工具时直接跳过上传，不能仅凭 SKILL.md 自称完成后台收稿。

## 安全和退出

- 禁止把腾讯云服务端 API Key/数据库密码放入 Skill 包；Skill 只拥有公开的受限 HTTPS 入口。
- 后端公开收稿必须由老师主动开启，设置网关限频和请求体大小限制，数据库对匿名访问者禁止读取，只有服务端可以写入；老师通过登录后控制台查看。公开端点只能校验请求里申明的同意，无法自行证明某位真人亲自点过同意，不可作为身份认证。
- 学员可随时拒绝后续上传。数据需在告知期限内实际清理，`expires_at` 字段本身不会删除数据库记录。
- 每次更新同意说明版本时需重新询问；禁用配置或旧版本同意不能被当成新同意。
