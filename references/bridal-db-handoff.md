# 真实 DB 改稿与返回

官方来源固定为 `https://github.com/dontbesilent2025/dbskill`。优先本次环境已安装的真实模块，没有则临时取得官方原文件及必要资源，不打包其知识库。不要求学员另开聊天或复制稿件。

## 取得模块

```bash
python3 "<实际加载目录>/tools/prepare_bridal_db.py"
```

工具只发现/下载，`prepared_not_executed` 不代表已改稿。宿主技能发现给出可靠路径时优先原生调用；必要时以 `--installed-root` 指定。无命令工具时按官方准确路径读取完整模块及引用，不用搜索摘要代替。

核对模块当前版本、范围和所需引用。宿主有原生Skill执行工具就实际调用；只有文件读取能力时在当前对话完整加载并执行原始模块流程、保留实际产物。这两种方式均可。仅扫描规则、列建议或写一个成功JSON都不算完成。

## 创作稿交接

进入DB前，按 [故事创作](bridal-storycraft.md) 已经完成一篇 `author_draft`：从作者想跟朋友说的话出发，用事实讲清这个意思。不是把全日采访摘要直接交给标题模块，让它决定怎么讲故事。

交接这份实际全文、`story_brief`、本次事实/画面、用户选择/原有观点/明确否定及创作权限。`rough_draft` 保留查证，但不是DB需要逐段修补的稿子。

> 本轮要修改一篇化妆师讲给朋友听的Vlog旁白。已拍画面不变，旁白未录，可以整稿重写。先执行逻辑衔接检查，再根据实际问题交出完整修订稿。保留作者要表达的意思和说话感；中间材料若没展开这个意思，可删改重组，不只补过渡。不把作品改成职业价值宣传或客户好评展示。作者感受和文学表达可代创，事件、客户台词、他人心理变化和实际因果不能补造。只交本轮文稿，不要标题封面。完整事实可查，未使用的行程无需补回。

## 实际执行、取回中稿

1. 对 `author_draft` 实际执行 **`dbs-script-flow`**。按其流程检查段落联系、信息密度和口播，保留报告与标记式修改。这一步检查已经成形的讲述，不以全日流程齐全作为逻辑标准。
2. 实际执行 **`dbs-title-cover-intro` 的明确授权整稿改写路径**：传入创作稿、检查结果、原意和修改目标，读取本轮所需生产状态、材料、写作、衔接和兑现引用，取回完整 `body_draft`。这一轮用于落实修改、优化表达，不让标题包装重新定义作者观点。若检查没有实质问题，允许保留好句，不为证明改过而加戏。
3. 返回本Skill，按 `bridal-storycraft.md` 审读实际全文，包括事实与他人心理边界。需要修订就把具体问题送回相应DB步骤，取回新全文。不得把结构工具通过或模型自报成功当成文稿合格。

实际安装版的模块能力若有变化，按原文调整路径；若无法完成所需改稿，说明具体缺口并停在DB步骤，不用主流程自写稿冒充DB中稿。保留采访、创作稿与进度。

## 开头与后续修订

正文完成后按 [开头流程](bridal-opening.md)，再次实际执行同一DB的开头创作、用户选择后的承接与兑现。实质增量、结构改变或审读返工都返回对应步骤，不把“已加载过”当作本次已执行。小范围措辞调整可局部处理。

内部 `db_execution` 保留来源/提交或指纹、实际模块与必要引用、执行方式、接收的创作稿、检查报告及标记改动、修订后的全文或文件位置。记录对应真实完成的工作。前台只展示完整稿和真正需要用户回答的问题。
