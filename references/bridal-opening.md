# 独立开头与全文装配

正文完成后实际进入同一DB开头模块。开头可以跳出第一件事或具体行程，单独形成有吸引力的观点、问题、情境或反差；全文必须承接其意思。

## 知识来源

依据代川项目“帮化妆师找好开头”的《拉宏开头写法研究报告》（2026-11-10），研究最近100条视频的前最多22秒、机器转写和300帧对照，非全片复核，转写未全部逐字校听。分类频率不证明流量效果。本包 [范式卡](bridal-opening-patterns.md) 提供机制和项目自写例句，手机端不依赖老师电脑或聊天。

## 创作、选择、装配

1. 从 `story_brief` 和正文提取作者想说的意思、目标观众、最有意思的张力和少量事实。用这个任务简报创作入口，别把任务设成“润色第一段”。模型仍可能记得正文，不声称隔绝记忆。
2. 实际读取范式卡，按适合的不同机制创作，保留2—3个确有区别的候选。每项保存 `id / mechanism / hook / next_line / first_shot / reason`。开头简短，一口气说得完；下一句进入具体事情。候选给用户选择，已有代选授权则代选并记录。
3. 选择后真实装入完整稿，修改接入段、重复介绍和必要的正文，检查承接与兑现。最终 `assembled.script` 从所选开头和下一句开始；需要调整承接句时同步候选并说明，不能暗换用户锁定的开头。重新整篇审读并更新 `reader_review`，最后再同步画面、原声位置。

检查开头单独听能否理解、有何继续听的理由、正文是否兑现；不同范式要改变吸引人的理由，不只改近义词。首画面只需进入处境或气氛，不用一个镜头证明全部修辞，仍只用已有素材。

用户允许夸张、幽默、强判断、比喻和少许明显超现实表达，不为普通修辞附免责声明；不能因此新增真实事件、经历、客户台词或结果。开头不够好就重写入口，正文接不住就改正文或换能承接的候选，不让学员补造故事。
