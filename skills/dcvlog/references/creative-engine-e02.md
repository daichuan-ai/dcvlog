# E0.2｜固定画面 × 动态案例驱动旁白引擎（实验版）

> 适用范围：只替换文案主体的生成策略。原有入口、认识学员、视频人数、标准镜头、四种开场、3—4秒结尾、成稿五项检查、拼图、统计与自愿回收继续执行。此文件优先于其他写作参考中与创作准入、案例调用、长度、语气重写冲突的旧规定；真实证据边界永远优先。

## E0.3｜保留采访，强化案例落笔与装配

采访引擎沿用 E0.2，不因本轮修改而强行提前出稿。写作前**实际阅读**匹配案例原文中的对应客人段落，内部提取镜头叙述顺序、每一段的叙述功能、语言密度、妆后展示位置，再使用本次事实重写对应段落。**不能只在回复里报告“参考了案例XX”却写成通用流水账。**不移植案例里的客户原话、订单数字或未发生的动作。无需向学员展示案例分析过程。

开场由 `opening-ending.md` 的四选一完成，切入口由 `interview-engine.md` 的五选一完成；交互呈现按 `interaction-display-e03.md`。最终连续旁白装配与质量检查按 `assembly-check-e03.md`，覆盖本文件原第7步中把五项教学说明全部作为默认交付的旧要求。

## E0.5｜创作前的可选视觉观察

采访结束后先执行 `@references/visual-observation-e05.md` 的一次可跳过邀请。照片只提供观众视角的风格与形象联想，不能替代真实采访事实。若上传，观察所得仅用于增强对应妆后描述；未上传直接写。工作范围不包括新娘跟妆。

## 核心定位
学员已经按统一的化妆Vlog镜头流程拍摄：妆前/到店、沟通、化妆过程、妆后照片和视频。AI不是重新发明短视频故事，而是按成熟化妆师案例的**可剪辑叙述顺序**写当天不同客人和妆容的旁白。与案例高度同构可以成立；不可把案例中的客人事实、真实原话、操作、结果照搬到新客人。可复用叙述结构与常规表达，避免逐字复制整段有独创性的文字。

## 工作顺序（内部执行，前台一次只问一个必要问题）
1. 保留原流程识别 `service_client_total` 和 `video_client_total`；按视频客人数逐一收集：用途/诉求、实际妆容/关键处理、可确认的妆后观察（可空）。默认标准镜头已拍齐。不要让学员解释抽象的审美术语；已足以描述这位客人时立即停止采访。
2. 用 `tools/case_catalog.py list` 读取动态案例清单（可执行时）；不能执行脚本则直接读取 `references/corpus/` 的 Batch001、Batch003 和 Batch002 新案例文件。**每次写稿都扫描 Batch002，不要求先“升级当前方法”。** 参考 `selection-guide.md`，优先按客人数/镜头结构，再按客人用途与风格，选1—2个最相近的完整案例或客人段落。
3. 先在脑中对应画面：开场镜头 → 第一位到店/妆前 → 需求与设计 → 过程 → 妆后照片和视频 → 后续客人依次缩短 → 结尾。首位重点完整，第二位突出一个新点，第三位以后可直接带作品；**本视频要求出现的客人一个不能漏**。
4. 沿用匹配案例的**信息进入顺序、段落密度、作品展示的落点和自然口吻**，将本次真实客人、用途、妆容与处理填入；不用强行造故事、冲突、金句、知识点或升华。语言可以灵活联想，但不得虚构真实评价、现场动作、交易数字、确定的妆后变化。缺妆后结果时可描述已确认的设计意图，给照片/视频留展示节点，不编“她很满意”。
5. **主体完成后再处理开场**：严格执行 `opening-ending.md` 的四种方向和素材核对；没有特殊开场素材默认客人直入，但也要写一条与客人画面对应的具体前5秒钩子，不把“今天两个妹妹”当作已经完成开场检查。
6. **结尾必须处理**：有真实人设特点则一句3—4秒收尾；不想要人设则自然结束，不强迫升华。结尾不是每次必须说固定句式，但必须检查是否有可用结束镜头/旁白。
7. 按 `delivery-checklist-e02.md` 核验后交付原版规定的五项：前5秒画面与旁白、唯一叙述重点、连续可念旁白、画面对应、一个简短练习收获。先给完整可用稿，用户试读后只修改明确不满意的局部；允许真正重写局部表达，不局限语气词。

## 事实不足时
- 如果连客人用途/妆容方向都没有，问一个最必要问题。
- 学员说不出来、连续卡壳或只提供几句话时，用已知事实写一份**可直接试读的初稿**；没有事实支撑的结果段仅写设计意图或留给作品画面，不要强制六项全部齐全才能开始写。
- 如用户愿意上传妆后照片，可直接观察照片帮助写具体结果；不能声称看过未提供的照片。
- 不改变已经确定的服务人数与本视频人数。若用户要求把尚无任何事实的客人写进去，先问该客人最基本的实际妆容，不凭空补人。

## 案例库维护
Batch001 与 Batch003 原文字节级锁定。Batch002 可持续添加 `B002-xxx.md`；新增后立即进入候选池，**不需要改 SKILL.md**。工具 `tools/case_catalog.py list` 每次实时扫描，`build` 可重建 `catalog.json`，`add` 保存新案例并重建索引。新增单例仅供模仿，不自动改全局方法。新案例同步到学生机器仍依赖后续可靠的跨平台更新系统。
