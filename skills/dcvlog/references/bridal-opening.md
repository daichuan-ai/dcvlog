# 独立开头与全文装配

正文完成后实际进入同一DB开头模块。开头可以跳出第一件事或具体行程，单独成立一个吸引人的入口；正文要接得住它。

## 本次材料与开头四要素

先从采访和正文提取下表内容，交给开头创作，不只是成稿后检查：

| 要素 | 找什么、怎么用 |
|---|---|
| 人群／身份 | 这条最想让谁停下来？把相关身份或处境写进开头，让那群人听得出与自己有关；可以是观众、化妆师或所讲人物。 |
| 具体场景／位置 | 找真实城市、酒店或场地名称，让当地观众认得出来；只写“今天在酒店”还不够具体。 |
| 数字／结果 | 找已确认的时间、距离、年数、数量、金额或具体结果；有用的尽量用，帮助听众一下理解事情的尺度。 |
| 情绪状态 | 找紧张、忙乱、兴奋、疲惫、感动等可表达的状态，用有力度、带极限感或适度夸张的短句放大吸引力。 |

身份和观众从已选主题确定；有用的具体地点、数字若缺失，可合并短问一次。记不清就舍弃，不为凑要素编造。四要素是选材方法，挑最有吸引力的组合进入前一两句，不把四项硬塞成报幕。

## 让范式组织材料

实际读取 [范式卡](bridal-opening-patterns.md)，把本次四要素、作者意思和故事张力交给DB开头创作。从适合的不同机制产生2—3个短候选；任务是重新设计入口，不是润色正文第一段。每项保留 `id / mechanism / hook / next_line / first_shot / reason`，说明吸引谁、为什么想往下听，下一句接入具体事情。候选机制要有区别，不只换形容词。给用户选择，已有代选授权则代选并记录。

作者情绪可代创，允许强判断、极限词、幽默、比喻和少许明显超现实表达；真实数字、地点、经历、客户台词和结果仍以材料为准。力度来自有意思的表达，不是无依据的事故、冲突或夸大承诺。

## 装入全文再口述编辑

所选开头和下一句实际进入 `assembled.script`，删重复介绍、改接入段，必要时调整正文。若需调整承接句，同步候选并说明，不暗换锁定开头。按故事创作文件对全文做一次实际口述编辑，确认观众听得懂在讲谁、为何继续听，正文兑现开头且讲出作者感受，再更新 `reader_review` 和声画提示。已有首画面负责带入处境，不必证明全部修辞。

范式卡依据代川项目《拉宏开头写法研究报告》（2026-11-10）：最近100条视频前最多22秒的机器转写及300帧对照，非全片复核，转写未全部逐字校听；分类频率不等于流量效果。卡片为项目提炼和自写例句，随包提供，手机端不依赖老师电脑或聊天。
