# 真实 DB 创作与返回

官方来源固定为 `https://github.com/dontbesilent2025/dbskill`。优先本次环境已安装的真实模块，没有则临时取得官方原文件及必要资源，不打包其知识库。不要求学员另开聊天或复制稿件。

## 取得模块

```bash
python3 "<实际加载目录>/tools/prepare_bridal_db.py"
```

工具只发现/下载，`prepared_not_executed` 不代表已改稿。宿主技能发现给出可靠路径时优先原生调用；必要时以 `--installed-root` 指定。无命令工具时按官方准确路径读取完整模块及引用，不用搜索摘要代替。

核对模块当前版本、范围和所需引用。宿主有原生Skill执行工具就实际调用；只有文件读取能力时在当前对话完整加载并执行原始模块流程、保留实际产物。这两种方式均可。仅扫描规则、列建议或写一个成功JSON都不算完成。

## 交接任务

传递本次事实与画面、用户选择/原有观点/明确否定、`story_brief`、`rough_draft` 和 [故事创作](bridal-storycraft.md)。已知信息直接复用，未知如实标记，不把空占位符交出去。

> 用户要求完整创作一篇可直接录音的新娘跟妆旁白，已授权整稿重写。画面已拍，旁白未录、可以重新写。请按你实际加载的模块流程执行本次任务，交出完整稿。事实粗稿供查证，不要求沿用其句子、段落和全日行程。先用普通话讲清这件事让作者想说什么，再围绕它选材料、组织完整讲述；先写作者要说的话，不沿粗稿逐段润色。中间经历需要让这层理解展开，不能只在结尾补一句观点。作者感受与文学表达可代创，事实和他人台词不可补造。用户的明确观点和已选事件保持；同一事件内可以收窄表达、改变详略，不重复发菜单。这里只需要本轮正文或开头，不需要标题封面。

## 先创作，再检查

1. 实际执行 **`dbs-title-cover-intro` 的整稿改写路径**。明确传入已有整稿改写授权，读取其本轮需要的生产状态、材料、写作规则、衔接及兑现引用。它当前允许明确要求时交出全文；把本项目的口语叙事目标作为任务意图，先形成完整创作稿。需要重新审视共鸣时可按原模块能力追加 `dbs-resonate`，不凑模块数量。
2. 对创作稿实际执行 **`dbs-script-flow`**，检查段落衔接、信息密度和口播，按其要求保留报告及标记式修改。它不负责替换观点或交出重写全文；不能让这一步决定一篇尚未形成的故事。
3. 将必要修改送回同一整稿模块形成可读正文，并按 `bridal-storycraft.md` 整篇审读。主线本身有问题就返回整体取舍和重写，不只补一条过渡。取得实际完整 `body_draft` 后才返回采访流程。

实际安装版的模块能力若有变化，按原文调整路径；若无法完成所需创作，说明具体缺口并停在DB步骤，不用自写稿冒充DB稿。保留原始采访与进度，不重做整场采访。

## 开头与后续修订

正文完成后按 [开头流程](bridal-opening.md)，再次实际执行同一DB的开头创作、用户选择后的承接与兑现。实质增量、结构改变或审读返工都返回相应创作步骤，不把“已加载过”当作本次已执行。小范围措辞调整可局部处理。

内部 `db_execution` 保留来源/提交或指纹、实际模块及必要引用、执行方式、创作稿、检查报告与标记改动、修订后的全文或其文件位置。记录应对应真实完成的工作，不以自己填写“成功”替代执行。前台只展示完整稿和真正需要用户回答的问题。
