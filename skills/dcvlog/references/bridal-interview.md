# 新娘跟妆｜采访、创作与交付

首屏选2进入。目标是写一篇化妆师能自然说出口、某群观众愿意听的旁白。采访尽量完整，成稿按表达目的取舍。只在相应阶段读取下列参考，不混入其他分支规则。

## 1. 按已有画面回忆

先请学员按当天顺序列拍到的画面。课程拍摄已经完成，不重新布置作业或要求上传全日素材。已有时间线直接复用。每轮问一个当前有用的问题，确认用✅、提问用❓，候选用数字独立列出。

画面用于唤起经历，采访重点是画面不能替本人说出的感受。弄清必要事实后，在有意味的节点顺势问一个问题：当时哪里触动了你、和原先想的有什么不同、现在回看最在意什么，或为什么这样做。按当前线索选问法，不逐节点填问卷，也不反复索取已经描述清楚的动作。关注关心、体谅、关系、审美取舍和普通人的处境，让化妆师说自己的理解，不用“是不是很感动”替她定感受。

回答不知道、没注意或说不出来时接受，继续收集其他线索。分别保留真实事实、本人感受及现在回看的认识；创作时由AI补足尚未表达的作者感受，不让小白为了写稿硬想感悟。需要找线索时参考 [因素](bridal-factors.md)，维度不是必填项。

记录真实事实、原话大意、已有观点、未知和声音是否录到。默认单兵工作；以实际描述为准，有助理或固定机位就记录，不把默认情况盖过用户事实。本人见过但没拍到可旁白讲述；不冒充现成镜头。

## 2. 选择值得讲的事情和作者表达

读取 [故事创作](bridal-storycraft.md)。用全日材料比较少量候选，事件优先于单纯讲人、物；小事、审美和普通处境也可成立。每个方向用自然话说清：具体发生了什么、化妆师想表达什么、谁可能有同感。推荐有依据且能展开的方向，让学员选择；不按人事物各凑一个，也不把“一天”“温暖”当作已经找到主线。

用户选定宽泛方向后，在同一事情内完成取舍和表达，不把后续每次写法调整再变成选择题。确需换事件、否定用户观点或补关键事实时才返回询问。只补影响成稿的缺口，不索取戏剧性或预想答案。

形成简短 `story_brief`：`event`（具体事情/处境）、`author_point`（作者想说的意思）、`audience`（谁为什么会在意）。它用于指导选材，不是逐段台词表，不预先规定感受句和结尾。后续可在用户已选方向内调整这份简报。

## 3. 资料底稿、作者讲述、真实 DB 改稿

保留按时间整理的全旁白 `rough_draft`，主要删减、归纳学员语料；它是可查事实的底稿，不是最终段落骨架。展示可简短，不新增批准步骤。实际已确认的语料、画面、作者原有观点和未知一并保留。

接着按 `bridal-storycraft.md` 写完整 `author_draft`：像化妆师本人向朋友讲述，从自己想说的意思出发选材料，可大幅取舍、重排和重写，不必用上全日画面。先将作者稿写入任务记录并完成整篇审读，再读取 DB 入口与引用；不要提前加载 DB 后才一口气生成三个阶段。随后实际执行 [DB交接](bridal-db-handoff.md)，取得DB检查修改后的完整中稿。资料底稿、作者创作和DB修改各自完成，不能跳过作者讲述而让DB润色流水账。创作权限集中在故事创作文件，不再执行旧的逐段感受配额。

## 4. 展示中稿与补充

得到实际 DB 完整 `body_draft` 并通过整篇审读后展示，问是否还有特别想讲的人、事、物。补充能增强本篇则加入，分散表达则说明舍弃理由；实质修改回同一 DB 创作，复用已有采访。纯措辞修正局部处理，不重启。

## 5. 原声与独立开头

读取 [声画交付](bridal-delivery.md)，只问少量真正值得用原声的位置；未知保留旁白。随后读取 [开头流程](bridal-opening.md)及其范式卡，实际用 DB 创作不同机制的短开头，给下一句、已有首画面与理由。等待选择，已有代选授权时直接选。用户提到剪辑或时长时正常回应，仍完成所需的开头选择和全文装配。

## 6. 装配与交付

所选开头进入完整全文，删重复、改接入段并按需要调整正文。按故事创作文件完成一次实际口述编辑：把仍在重复画面、轮流转述对白的部分改成作者想讲的意思，再交连续旁白和逐段声画提示。感受贯穿表达，不按段配额，不固定结尾或字数。

从粗稿开始在当前任务私有目录维护 `creative-work.json`：`schema_version:2`、事实/画面及用户选择、`story_brief`、`rough_draft`、`author_draft`、`body_draft`、真实 `db_execution`、`opening_candidates`、`opening_choice`、`assembled.script` 和最终 `reader_review`。检查工具只核对这些交接及稿件版本，不评分文笔：

```bash
python3 "<实际加载目录>/tools/check_bridal_creative.py" "<当前任务目录>/creative-work.json"
```

按 `return_to` 补缺失部分；质量问题由整篇审读解决。无文件/执行工具时在上下文保留同样产物，如实说明未运行结构工具。恢复旧版记录时复用原采访、粗稿、用户选择和现有全文，形成简报并重做整篇审读；旧 `emotion_plan`、逐段摘句和结尾字段不再是成稿条件，不让学员重答已知信息。
