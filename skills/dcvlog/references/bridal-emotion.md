# 作者感受线｜粗稿之后、DB正文创作之前

适用于选2。先读事实粗稿、已选事件/切口、目标观众、学员已有观点与明确反对的解释，再执行本阶段。学员不擅长表达感受时由AI完成，不增加一轮“你到底怎么想”的必填采访。

## 创作权限

**用户明确授权AI代创讲述者的感受、态度、观点、联想和文学化表达，包括语料中没有直接说出的感受。** 不要求每句话由学员先说出，不逐句索取“你真的这么想吗”的确认。学员在完整创作稿中整体选择、删改。已有明确观点优先；学员明确否定的解释不再写入。

事实记录与创作表达分开：事件、人物关系、做过的动作、客户原话、已拍画面和录音保持素材边界；作者的第一人称感受可以艺术化创作。不能把代创的感受登记成采访原话，也不能把作者的文学判断改成客户亲口说过的原因。用户要求的“被幸福冲昏头脑”可以作为浪漫感叹，不需要心理测量依据；不要写成“新娘告诉我，她因为太幸福才忘了流程”，除非确有这段自述。

允许轻微虚构作者当时的心情或现在回看的体会，用“我觉得、看着她、这才发现、原来……”自然表达。可以直接作出有个人味道的判断，不每句加“可能、似乎、仅代表我”。没有情绪语料不是阻止创作的理由。表达让学员说得出口、观众听得懂，可以有文学色彩，不写成论文或一串空泛金句。

## EMOTION_PLAN：先产生三个内部产物

1. **中心判断** `center_judgment`：用一句大白话说明这件事让作者觉得什么。它是文章要表达的感受/看法，不是“讲新娘的一天”这样的内容目录。
2. **感受推进** `progression`：按主要事实段落逐项记录“事实节点 → 作者会怎样感受/判断 → 这句怎样服务中心”。每个主要事实段落有简短作者回应，相邻同类段落可以共用，纯转场不机械塞一句。感受能变化，不能每段重复“太感动了”。
3. **结尾落点** `ending_response`：准备在最后的事实之后，作者还要说出的那句感受、观点或文学回扣。不能只把人物原话再说一遍就算完成。

`progression.response` 必须写成可以进入旁白的作者感受句，不写剪辑/写作安排，不用人物动作代替。只有主线的重要情感节点进入推进表；纯转场留在事实底稿，不为了把所有素材填满而占一个感受位置。

这些产物保存在当前任务的 `creative-work.json`，不让学员填写或阅读内部表。候选中心若需要改变已选切口或与学员明确观点冲突，才交回选择；普通感受代写直接进行。

## BODY_DRAFT：交给真实DB执行创作

向DB提供事实粗稿和情感方案，明确要求写成“事实推进＋讲述者回应”，不是把感受集中到最后一段，也不是在流水账后面随意插几句感叹。可以重排、删减和重写正文；无关事实即使真实也可删。

例如材料里有“新娘一路问时间和路线”，作者可判断“结婚是真的忙”；有“妈妈问大家吃饭没有”，可以写“忙归忙，妈妈还惦记着大家有没有吃饭”。它们要共同呈现本篇中心，不能突然另开一篇母爱故事。这是表达方式示例，不是每条视频的固定答案。

“幸福、温暖、忙碌、好看与舒服、人与人的分寸”等都可以成为中心，也可幽默、心疼或有态度；根据本次事件与目标观众选择，不默认所有婚礼必须幸福感动。作者不是只负责出现在第一句的“我”，要能从正文里听出她怎么看。

## 必做的作者感受复核：写正文之后再执行一次

重新对照实际正文，单独产出 `emotion_review`，然后才能展示中稿；装配后再对最终全文更新这份复核，并放入 `assembled.emotion_review`；字段见下文，结构工具会检查实际摘句和最终结尾是否一致。工具仍不判断文学质量。它不是学员的新问题，AI内部完成。

- `author_position`：用一句普通话说明“这件事让我觉得怎样，我为什么这样看”。不能只填人物做了什么。
- `beats`：逐个主要情感节点摘出 `fact_excerpt / feeling_excerpt / adds`。前两项是正文实际摘句；`adds` 用大白话解释作者感受比事实多说了什么态度。片子很短可以只有一两个节点，多段故事要有前、中、后的推进，不能只在开头和结尾各塞一句，中间全是记录。
- `ending_feeling`：实际全文最后的作者感受摘句。核对最后是否超出“发生了什么”，表达“我因此觉得什么”。

**先判断类别，再判断文笔。** 以下四种东西不能冒充作者感受：

| 写出的东西 | 为什么不算 | 要补的内容 |
|---|---|---|
| “她拿着手机回消息”“说完我们换衣服” | 还是人物动作与时间推进 | 作者觉得她忙得可爱、心疼、好笑，或由此理解了什么 |
| “压缩为呼吸段”“交给画面”“反衬主线” | 是制作安排，观众听不到作者态度 | 写成实际可说的感受句，或把纯转场移出感受表 |
| “我当时没多想”“现在才反应过来” | 只有思想入口，没有思想内容 | 接上具体判断，让观众知道作者反应过来了什么 |
| “她问了一天，最后都走完了”“这是少有的不带问号的话” | 概括或文学观察可以保留，但仍可能只是换一种说事实 | 再有作者对这种处境的情感回应；不能仅凭修辞就认定感受线齐了 |

例如同样是“客人摘下头饰，说脖子轻了”，作者可以回应“听她这么说，我也跟着松了一口气，好看这件事，还是得让人舒服才算数”；同样是“一整天都在确认安排”，可以感叹“原来结婚是真的忙，连做今天的主角，都没空停下来”。作者感受也可更短、更朴素，不必每句讲道理。这些示例只说明从事实走向作者态度的区别，不能照抄成每篇固定答案。

暂时遮掉事实句，只读感受摘句：是否听得出一个有态度、有反应的人，是否能讲清同一个中心？如果只能读到动作概括、文学改述或制作安排，`emotion_review` 不通过，回同一DB重写这些主要段落，不要求学员再回答感受。不以“用户选了这个事件”推导“用户禁止作者下判断”。学员只否定某个具体解释时，只排除那个解释，其他贴合事实的感受仍然代创。

## 检查与返回

- “我才反应过来/我才发现”后，写清发现了什么；单独留这个转场等于没有观点。
- 逐个主要事实段落找实际的作者回应，不能用事件复述冒充感受。把正文里真实写出的感受句摘入 `emotion_evidence`；摘不出就回本阶段安排，再由同一DB重写受影响段落。
- 感受推进是否共同形成中心？出现互不相干的几种道理，回到 `EMOTION_PLAN` 收束，再写正文。
- 结尾是否在事实之外增加作者回应？若只停在客户“脑子有点空”等事实，返回结尾创作；用文学化判断回收前文，而非强制人生大道理。
- 感受与事实是否混淆、是否重现学员否定的观点？修改相应表达，不因允许感受虚构就新增事故、伤害、客户评价或不存在的镜头。

正文通过后，才进入中稿展示和补充确认。结尾与开头之后还可以在装配阶段一起调整；用户确认正文不等于把表达冻结。结构检查工具只检查产物完整，不能代替本节的写作判断。
