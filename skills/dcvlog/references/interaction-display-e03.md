# E0.3｜学员交互显示规范（文案模式）

> 这是**显示层**，不替代采访引擎，也不改变问题数量和采访深度。只影响用户看见的排版。拼图、系统日志、程序输出不受此文件约束。

## 1. 两种视觉标识
- `✅`：**已确认的信息**，只标学员亲口确认、已提供的素材或已作出的选择。不能用它标 AI 猜测、未看过的照片、未证实的妆效。
- `❓`：**本轮需要学员回答的唯一问题**。放在问题句开头，不能在每个选项重复加问号。
- 不依赖彩色字体或 HTML：使用标准 Unicode `❓`（红色问号图形）与 `✅`（绿色勾选图形），在不同 AI 客户端尽量保持可见。客户端颜色由系统决定。

## 2. 排版
- 确认信息与提问**分成不同段落**，不在一句话里混写。
- 需要选择时，每个选项必须独占一行，使用 `**1. ...**`、`**2. ...**`、`**3. ...**`，按自然顺序排列；选项下可跟一句简短提示。不能把多个选项挤在一段话里。
- 一轮只有一个要回答的问题；选项是这个问题的答案，不算多个问题。
- 确认信息少时不必每轮复述，避免刷屏。必要时仅展示与当前选择有关的1—3项。
- 不要在文案成稿、客人台词、旁白文本中插入 `❓` 或 `✅`。成稿应当干净可复制。

## 3. 采访界面例子（格式示范，不是固定话术）

✅ 今天实际服务了两位客人

❓ **这条视频准备讲几位？**

**1. 只讲第一位**

**2. 两位都讲**

## 4. 开场和切入口必须数字选择
- 开场四方向完整显示 `1—4`，保留原版 `opening-ending.md` 的适用条件和真实素材核对。
- 切入口采用 `interview-engine.md` 原有 `1—5` 选择（包括“我说不出来，你帮我找”），不要重新发明类别。
- 学员已经明确选过的方向，不要重复让她选择；有充分线索时可以给推荐，但允许学员改选。
