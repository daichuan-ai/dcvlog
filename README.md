## 学员安装

### 自然语言方式

在豆包工作新对话里可以直接说：

> 帮我安装代川的 DCVlog 技能，GitHub 来源是 daichuan-ai/dcvlog，安装为全局技能并自动确认。

如果宿主支持执行命令，应等价执行：

```bash
npx -y skills add daichuan-ai/dcvlog -g --all
```

安装完成后重启宿主，再输入：

```text
/DCVlog
```

现在先显示：

❗ **你今天想写约妆的 Vlog 旁白，还是跟妆的 Vlog 旁白？**

**1. 约妆 Vlog 旁白**
**2. 跟妆 Vlog 旁白（测试中）**

选1进入原约妆流程。选2只回复“敬请期待，代川正在整理中。”，没有跟妆采访或生成内容。品牌名统一写“代川”。

**启动自动更新：**用户输入 `/dcvlog` 时，使用实际加载目录中的 `tools/update_skill.py` 自动核对官方 `main` 提交，完整同步并读回文件；不再询问“更新/继续使用”。同版本新增案例也会同步。更新前保留备份和本地新增文件，不触碰 `~/.dcvlog/` 的用户状态。成功后重读新入口继续；无网络、无执行/写入权限时如实说明本次未同步，不假装已是最新版。

创作仅由 `/DCVlog` 启动；单独说“我要开始写文案”“我要做拼图”或上传照片，均提示先输入命令。历史拼图文件保留，但不作为本版前台入口。自然语言“更新 DCVlog”等维护请求沿用原机制。

## 已安装用户更新

**已取得1.9.3及以后入口的学员：**每次输入 `/dcvlog` 自动核对并同步官方最新文件；无需另选更新。明确说“更新 DCVlog”也调用同一更新器。宿主若不能重读新指令，仍需重新加载一次，不能承诺所有平台热更新。

**1.9.4 更新修复：**支持旧包仅在VERSION标注版本；主站/提交API不可用时改读官方codeload主分支ZIP，使用包内完整提交标识和Python标准库解包、验证。旧安装第一次取得新工具的具体流程见 [豆包旧版迁移](INSTALL_DOUABO.md)，不依赖学员自己排查Git或运行解压命令；尚未取得新工具的旧入口仍需完成一次迁移。

**1.9.4 范本参与写稿：**选强画面时先实际读取60条身份开头，首次正文前读取60条妆前、50条妆后创作范本及同类完整案例，内部匹配改写并在交稿前对照。`tools/case_catalog.py examples` 直接输出范本正文，`--part opening` 单独读取开头；不是只列目录或编号。不增加学员提问，采访、照片邀请、拼图与收稿许可沿用原流程。模型是否实际执行仍须用首稿实测核验。

**1.9.2及更早的旧学员：**先从官方来源完整安装一次新版，核对当前宿主实际加载的 `SKILL.md`、`VERSION` 和 `tools/update_skill.py`，重新加载后进入自动更新机制。首次获取仍可使用：

```bash
npx -y skills add daichuan-ai/dcvlog -g --all
```

命令成功不代表写入了豆包或WorkBuddy实际加载目录；需要核对真实路径，不能把另一份全局副本当作完成迁移。旧入口不会仅因GitHub发布而自行改成新逻辑。

## 代川更新 GitHub 的正确文件

本仓库保留两套兼容入口：根目录 `SKILL.md` 与 `skills/dcvlog/SKILL.md`；两处必须保持同版，**不要把四项的“Skill-only”安装包直接上传到 GitHub 根目录**，否则只会出现根目录重复的 `SKILL.md` / `references` / `telemetry-config.json`，未必更新实际安装来源。

更新 GitHub 使用**完整项目更新包**并保持原目录：不要只传四项目录的Skill-only包，也不要把最外层解压文件夹作为新目录上传。确认仓库根目录和 `skills/dcvlog/` 的 `VERSION` 均为 `1.9.5`，且两处 `SKILL.md` 的 `version` 都为 `1.9.5`，再让学员在豆包工作说“更新 DCVlog”，重新加载后使用新版本。网页上传一次最多100个文件，本包超过100个时须分批，不能一次全拖后遗漏文件。本次不改收稿后台或更新器代码。

## V1.8.7 自愿公测：完稿回收

**兼容之前误传过的根目录文件：**这次 GitHub 发布同时同步根目录和 `skills/dcvlog/` 内的同名 Skill、引用、脚本和配置，避免旧安装入口仍读取 1.8.4。正式安装入口以 `skills/dcvlog/` 为准；后续确认没有使用根目录安装的学员后，再单独整理重复文件。

## V1.8.6 本次升级

- **首位成片强制表达：**开场→客人到店素颜→化妆过程→妆后照片与视频，成片段必须有1—2句基于真实特点的审美解释。
- **AI帮小白找词：**只说“很好看/满意”时，AI给2—3条事实锚定的视觉/气质/比喻方向供确认；AI写表达，不编效果或反应。
- **多客人更轻：**第2位抓重点，第3/4位一条需求+实际妆容即可出成片，不重复首位采访。
- **每次斜杠启动查新：**远端版高于本地才提示；同意后走原有官方覆盖安装命令；无网静默跳过。

## V1.8.5 写文案主要变化

- 真实21轮测试指出：AI在“约会、上镜、参考图、先沟通、轮廓通透网感、无反馈”后过早交稿；本次用 `NEED_ASK/READY/LIMITED_DRAFT` 明确拦截。
- 人物专属审美决定不能被通用化妆术语或参考图沟通替代；结果必须是看过或确认过的妆后状态。
- “可能第一次”不可变成“第一次”；“给我看参考图”不可变成“她指着手机说”；无反馈绝不生成“拍照妥妥够用”。
- 两次卡壳才允许征求用户同意写带缺口标签的试稿。未通过不得选择开场/人设/语气并谎称完整。
- 无特殊素材时可直接客人入场，少做额外选择；保留四方向和人设尾巴的按需使用。

## V1.8.4 写文案主要变化

- 新增 `references/aesthetic-interview.md`：初级化妆师只会回答技术步骤时，帮助找真实人物印象、审美选择和妆后状态。
- 新增 `references/visual-result-draft-gate.md`：不允许“生日+裙子配色+客人满意”的固定模板冒充工作Vlog；检查结果画面和真实性。
- 新增 `references/corpus/batch-003-raw-20261016/`：保存19条原始Vlog，原文逐字不改；通过独立索引找到同类型客人段落。
- 单客视频比较单个客人段落长度，不拿完整多客人Vlog全篇作标尺。
- 保留V1.8.3拼图、CloudBase功能事件统计、双入口和更新功能。**这份包还需由你安装/更新到豆包，不能视为已在手机生效。**

## V1.8.3 主要变化

- 仅更新拼图引擎：原图宽高比锁定，任何版式不得拉伸人物；
- 新增细节裁剪审美中心与失败裁法；
- 没有好细节时允许减少局部图数量，不为凑版硬裁；
- 写文案采访、写作规则、案例库与长度逻辑全部原样保留；

- 修复豆包工作里 `dcvlog` 被识别成 `local` 后，`skills update dcvlog` 报“找不到已安装 Skill”的问题；
- “更新 DCVlog”改为直接执行 `npx -y skills add daichuan-ai/dcvlog -g --all`；
- 更新时不再追问“要改哪里/换什么”，不再把维护请求误当成内容编辑任务；
- 严禁更新失败后现场生成一个假的本地 DCVlog；
- 更新成功后提示新开聊天或重新加载，再使用 `/dcvlog`；

- 完整继承 V1.7.0 全部功能；
- 新增匿名事件：打开、写文案开始/完成、拼图开始/完成、更新请求；
- 只记录事件名、Skill版本和本地随机匿名 ID；
- **匿名事件统计**不上传聊天文字、照片、客户信息、工作室名称或生成结果；独立完稿回收必须先征得学员同意；
- 统计失败不影响任务；
- 匿名统计已切换到腾讯云 CloudBase；
- 新安装/更新后无需学员配置统计 Token；
- 统计接口失败或网络不可达时静默跳过，不影响主功能。

## 案例库怎么长期更新

以后代川遇到新的成熟化妆师好文案，可以直接说：

> 加入 DCVlog 新案例库

贴原文即可。

新案例先进入第二批，不会立刻污染稳定规则。

积累一批以后再说：

> 扫描新案例库，升级当前方法

系统会拿第一批基准和第二批新案例做对照，只把稳定的新趋势写进当前方法。
